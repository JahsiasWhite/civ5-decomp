# Function boundary fixes: <entry> <end-exclusive> [new]  # why
#
# Ghidra sometimes splits one function in two, usually at an early `ret` with more
# code after it that is reached only by a jump from the first part. Neither piece
# can match, because the compiler only emits whole functions. A line here makes
# the function at <entry> span [entry, end) as one range, and drops every function
# entry that starts inside it (split-off pieces, or entries Ghidra misread from the
# middle of it). `new` marks a function Ghidra did not list at all; it is added.
# All tools read data/functions.csv through this
# (tools/config.py load_functions), so scope, queue, task bundles, fingerprints and
# `manage.py push` (which updates the server) all see the fixed boundaries.
#
# `python tools/c5d.py boundaries` finds candidates (splits, and listed entries that
# sit inside another function's code); `--write` appends them here.
# After editing: `c5d scope`, `c5d queue` (rewrites data/callgraph.csv), `c5d fingerprint`,
# then push to main.
